# learning-curve — notes for coding agents

- Nx + pnpm workspace. `apps/web` is a thin TanStack Start shell (React 19, file routes in `apps/web/src/routes`, server functions in `apps/web/src/server`, Vite 8, Nitro). `modules/*` are build-time microfrontends with Feature-Sliced layers inside. `apps/mcp` is the MCP server, `apps/docs`, `apps/docs-harness` and `apps/stand` the guide, its test host and the component stand. `packages/*`: `plan-domain` (pure TS, one entry per area: `.`, `./insights`, `./protocol`, `./ics`, `./sync`, `./rebalance`, `./fixtures`), `plan-content` (the owner's courses), `plan-service` (ports, use cases, `./testing`), `plan-data` (Node adapters: `./fs`, `./ical`, `./highs`, `./google`, `./outlook`, `./local`), `docs-contract`, `remote-host`, `i18n`, `ui`. Read `docs/architecture.md` before adding a file: it says where things go and what may import what.
- Layer rule, one `type:` tag per project (`nx.tags` in `package.json`): app → anything below; module → domain, contract, shared; infra (`plan-data`) → service, domain, content, contract; service → domain; content → domain; domain and contract → nothing; shared → contract. `scripts/check-graph.ts` enforces it on the `workspace:` dependencies and `pnpm run check` runs it first; add a dependency only if it passes. Lint enforces it on imports (`.oxlintrc.json` overrides, `steiger.config.ts`). Modules never import each other, `@lc/plan-data/*`, `@lc/plan-service`, `@lc/plan-content`, `node:*` or server functions: the app passes data and callbacks in as props (`PlannerPage` takes `plan`, `url`, `abilities`, `slots`). Inside `plan-domain` the areas depend one way (core ← insights ← protocol; core ← ics ← sync; core ← rebalance); a folder becomes a package only when it needs another layer, a deployable needs it alone, or it changes on its own cadence. Imports inside a package are relative; other packages are imported by name through their public entry.
- Packages are consumed as TypeScript source (no build step, `exports` point at `src`). Do not use a path alias inside `modules/*` or `packages/*`: the app type-checks their sources with its own tsconfig.
- Source of truth for the schedule: `packages/plan-content/src/content.ts` + `schedule.ts`. `packages/plan-data/data/plan.json` is generated by `pnpm run plan`; never hand-edit it, regenerate. Manual changes made in the viewer live in `packages/plan-data/data/edits.json` (event patches by uid, renamed and added calendars, added events, calendar `order`, `hidden` calendars, calendar `labels`, `weekNotes`: the kept week reviews, the weekly `budget` and `dayLimit` from Settings, `removed`: the trash, purged after 30 days by `purgeTrash`) and are applied by the same command. Every edit is a `PlanChange` handled by `applyChange` in `packages/plan-domain/src/core/changes.ts`: add a new kind of edit there, not as a new server function; `packages/plan-data/src/fs` is the only code that writes either file. Undo and redo are not edits: each stored change is a step of `PlanHistory` (`packages/plan-domain/src/core/history.ts`, kept in the untracked `data/history.json`) and moving along it replaces the edits with that step's snapshot.
- A chat or a tool changes the plan with an *update*, a list of `PlanChange` values (`packages/plan-domain/src/protocol/update.ts`). Its JSON Schema (`schema.ts`), the guide a model reads (`guide.ts`) and `parseChange` describe one protocol: change them together and run `pnpm run test`, which fails when they drift. A plan operation is a use case in `packages/plan-service` (`createPlanServices(ports)`) written against ports, answering `Result<T, PlanFailure>`: failures are values, mapped to HTTP in one place (`apps/web/src/server/respond.ts`). The MCP server (`apps/mcp`, `pnpm run mcp`), the `/api/plan-*` routes and the `AI chat` tab are thin adapters over the services: put no rules in them, and add a new store or outside service as an adapter of a port (with `@lc/plan-service/testing` contract suites), not in a use case. To change the plan as an agent in this repository, prefer the MCP tools (`get_guide` first) or `POST /api/plan-update` over editing `edits.json`.
- Plan files with versions live in the untracked `packages/plan-data/data/library/`, written only by `packages/plan-data/src/fs`.
- After changing content or rules: `pnpm run plan && pnpm run check && pnpm run test && pnpm run build`.
- Before finishing any change: `pnpm run check` (typecheck, Oxlint, Steiger, translation check, Oxfmt check). Format with `pnpm run fmt`. One project: `pnpm exec nx run @lc/planner:typecheck`.
- Weekly study budget is 12 h; `pnpm run plan` warns when a week exceeds it. Gym and Saturday buffer do not count.
- Times are Europe/Minsk wall-clock strings; use the date helpers exported by `@lc/plan-domain`, never `new Date(localString)`. Locale-aware date and hour text comes from `@lc/i18n/format`.
- UI text is localized (ru base, en, es) with Paraglide JS: add every string to all three `packages/i18n/messages/*.json` files and call it as `m.key()` (`import { m } from '@lc/i18n/messages'`); never hardcode UI text. Run `pnpm run check:i18n` after editing messages. `packages/i18n/src/paraglide/` is generated, never edit it. Plan content stays Russian. Code and docs are English. Event titles: `<Course short name> — <Module / topic>`; descriptions: course URL, module URL, 1–3 line goal.
- Types are strict beyond `strict`: `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` (an optional prop that callers may pass `undefined` to is `name?: T | undefined`) and the type-aware Oxlint rules in `.oxlintrc.json`. No `any`, no `as`, no `!`: narrow with a guard, `.at()`, destructuring or a restructure. A promise started on purpose is `void work()`; two calls in a handler are a block, not `(a(), b())`.
- TypeScript 7 has no compiler API: tools that need it (typescript-eslint, the Nx TypeScript and boundary plugins) do not run here.
- Shared dependency versions live in the `catalog` of `pnpm-workspace.yaml`.
- `apps/web/src/routeTree.gen.ts` is generated by the router plugin.
- Commits follow Conventional Commits; commitlint enforces it in a `commit-msg` hook.
