### Идея в одном абзаце

Module Federation позволяет одной сборке (**remote**) опубликовать часть своих модулей, чтобы другое приложение
(**хост**) могло импортировать их через `import` во время выполнения, по URL, как будто они часть его собственного
бандла. Две сборки ничего не знают о файлах друг друга. Договариваются они только о трёх вещах: имя (`lc_docs`), модули,
которые предлагаются (`./help`), и зависимости, которые они будут делить, вместо того чтобы скачивать их дважды (React).
Всё остальное — имена чанков, хеши, где лежат файлы — выясняется во время выполнения.

Глава «<ChapterLink id="build-time-microfrontends" />» поставила стены между модулями и компоновала их в бандлере. Эта
глава сохраняет стены, но переносит компоновку в браузер — для одной части: этого руководства.

### Что происходит при первом клике

Когда кто-то нажимает в планировщике **Как это сделано**, происходит вот что, в том порядке, в каком это показывает
вкладка Network:

1. Хост импортирует чанк своего загрузчика через `import()`, и тот подтягивает рантайм федерации. До этого момента на
   странице не было ни того ни другого.
2. Рантайм запрашивает `mf-manifest.json` с origin руководства. В манифесте указаны файл точки входа remote
   (`remoteEntry-<hash>.js`), то, что remote предоставляет, и то, какие общие зависимости он ожидает, с версиями.
3. Рантайм импортирует точку входа remote. Манифест объявляет её ES-модулем (`"type": "module"`), а на модуль,
   загружаемый с другого origin, распространяется CORS: хостинг руководства должен отвечать с
   `Access-Control-Allow-Origin`.
4. Точка входа инициализирует **share scope**: хост уже зарегистрировал там свой React, поэтому remote берёт эту копию,
   а не скачивает собственную запасную.
5. `get('./help')` загружает чанки `src/remote/help.tsx` и возвращает фабрику; её вызов отдаёт модуль.
6. Хост проверяет форму модуля и версию контракта и только после этого вызывает его код.

Каждый шаг может упасть (офлайн, CORS, устаревший манифест, несовместимая версия), поэтому каждый обёрнут. Код ниже —
это всё, что есть.

### Remote: один плагин, один открытый модуль

Сайт руководства собирает TanStack Start. Remote — это вторая, обычная Vite-сборка тех же исходников с добавленным
плагином федерации:

<Walkthrough>

```ts file=apps/docs/vite.remote.config.ts at=main

```

<WalkStep lines="1-3" title="Папка на каждую мажорную версию">

Remote пишется в `remote/v1/`. При ломающем изменении контракта рядом собирается `remote/v2/`, так что хост, собранный
под версию 1, продолжает работать, пока его не обновят.

</WalkStep>

<WalkStep lines="14-15" title="Один диапазон React для обеих сторон">

Remote принимает любой React `^19.3.0`. Хост даёт свою копию; диапазон решает только то, может ли remote использовать её
без предупреждения.

</WalkStep>

<WalkStep lines="18-20" title="Никаких вшитых адресов">

`base: './'` вместе с `publicPath: 'auto'` (строка 48) делают URL каждого чанка относительным к манифесту, который
загрузил хост. Одни и те же файлы работают с `localhost:4310`, с GitHub Pages под `/learning-curve/` или с любого
другого origin.

</WalkStep>

<WalkStep lines="21-24" title="Адреса времени сборки обнулены">

Сайт берёт свой origin и адрес стенда из переменных `VITE_*`. Внутри хоста они были бы неверными, поэтому сборка remote
их опустошает: выдвижная панель берёт адрес сайта из контекста, который передаёт хост (`siteUrl`).

</WalkStep>

<WalkStep lines="29" title="HTML на входе">

Vite собирает от HTML-точки входа. `remote.html` — заодно маленькая страница, чтобы попробовать панель без хоста. Хосты
её никогда не загружают: они идут через точку входа федерации.

</WalkStep>

<WalkStep lines="36-40" title="Имя, точка входа, exposes">

`name` — глобальный идентификатор контейнера (`lc_docs`). `exposes` сопоставляет публичное имя (`./help`) приватному
файлу — та же идея, что `exports` у пакета. Файл точки входа получает хеш содержимого, потому что GitHub Pages кэширует
каждый файл на десять минут (глава «<ChapterLink id="shipping" />»).

</WalkStep>

<WalkStep lines="41-46" title="Что общее">

React, ReactDOM и две точки входа, которые код действительно импортирует (`react/jsx-runtime` для скомпилированного JSX,
`react-dom/client` для `createRoot`), объявлены singleton. Роутер намеренно не общий: у панели свой memory-роутер, и она
не должна зависеть от того, какая версия роутера у хоста.

</WalkStep>

<WalkStep lines="47-49" title="Манифест включён, генерация типов выключена">

Манифест — это то, что загружает хост. Генерация файлов типов выключена, потому что типы живут в пакете контракта,
который импортируют обе стороны (глава «<ChapterLink id="docs-remote" />»).

</WalkStep>

</Walkthrough>

### Хост: рантайм без плагина

Сборка планировщика не затронута. Плагин федерации в ней не работает, а её серверный рендер не знает о существовании
remote. Вся федерация на стороне хоста — один файл, который загружается по требованию:

<Walkthrough>

```ts file=packages/docs-host/src/load.ts at=main

```

<WalkStep lines="1" title="Не в первом бандле">

До этого модуля добираются только через `import('./load')`. Бандлер кладёт его вместе с рантаймом и его зависимостями в
чанк, который скачивается при первом клике.

</WalkStep>

<WalkStep lines="10-14" title="API рантайма и собственный React хоста">

`createInstance` из `@module-federation/runtime` — обычная функция. Четыре импорта React — это копии хоста, которые он
сейчас предложит remote.

</WalkStep>

<WalkStep lines="35-42" title="Предложить общий модуль">

Каждая запись в shared говорит, какая версия есть у хоста и как её получить (`lib`). `singleton` означает одну копию на
страницу: два React в одном дереве ломают хуки. Комментарий фиксирует, что происходит при несовпадении: предупреждение —
и всё равно эта копия.

</WalkStep>

<WalkStep lines="44-52" title="Сбросить кэш для единственного фиксированного имени">

Манифест — единственный файл remote без хеша в имени. Query-параметр, который меняется при каждой загрузке страницы,
означает, что браузер никогда не ответит на этот запрос из своего кэша.

</WalkStep>

<WalkStep lines="54-60" title="Дедлайн">

Зависший remote оставил бы кнопку крутиться вечно. По умолчанию через восемь секунд загрузка завершается ошибкой, и хост
показывает запасной вариант.

</WalkStep>

<WalkStep lines="63-73" title="Зарегистрировать remote">

Remote регистрируется по имени, а точкой входа служит URL его манифеста. Именно `.json` в URL точки входа говорит
рантайму сначала прочитать манифест; query-параметр против кэша этому не мешает.

</WalkStep>

<WalkStep lines="74-80" title="Загрузить и назвать ошибку">

`loadRemote('lc_docs/help')` выполняет шаги 2–5 из списка выше. Любая ошибка превращается в `DocsLoadError` с причиной,
так что UI может отличить «истекло время ожидания» от «недоступен».

</WalkStep>

<WalkStep lines="81-88" title="Доверяй, но проверяй">

Всё, что пришло по сети, — `unknown`, пока не доказано обратное: сначала форма, потом версия контракта. Remote, который
реализует другую мажорную версию, отклоняется до того, как хоть какой-то его код выполнится в дереве хоста.

</WalkStep>

</Walkthrough>

### React-хук поверх этого

Планировщик и тестовая обвязка используют один и тот же хук, поэтому правила загрузки записаны один раз:

<Walkthrough>

```ts file=packages/docs-host/src/use-docs-host.ts at=main lines=47-121

```

<WalkStep lines="58-63" title="Свежие значения без пересоздания">

Панель создаётся один раз. Хук хранит последние контекст и обработчики событий в ref, так что хост, который передаёт
новый объект на каждом рендере, не вызывает перезагрузку.

</WalkStep>

<WalkStep lines="65-69" title="Изменения контекста становятся обновлениями">

Когда меняются локаль, тема, фича или токены, живая панель получает `update()`. Объект токенов сравнивается по значению
через `JSON.stringify`.

</WalkStep>

<WalkStep lines="81-95" title="Загрузить один раз, по требованию">

Первый `open` запускает загрузку и сохраняет промис, поэтому два быстрых клика загружают remote один раз. Динамический
`import('./load')` — та самая строка, которая не пускает федерацию в первый бандл хоста.

</WalkStep>

<WalkStep lines="97-116" title="Мягкий отказ, повтор позже">

При ошибке сохранённый промис сбрасывается, и `open` разрешается в `false`: хост показывает ссылку на статический сайт,
а следующий клик пробует снова, потому что remote мог вернуться.

</WalkStep>

</Walkthrough>

### Одна сборка, любое окружение

Где задеплоено руководство — это значение времени выполнения. Планировщик читает его на сервере, когда приходит запрос,
а не во время сборки:

```ts file=apps/web/src/server/docs.ts at=main

```

Staging- и production-планировщик могут работать на одной и той же сборке и смотреть на разные руководства или ни на
какое: в production-сборке без `DOCS_REMOTE_URL` кнопка не показывается. В разработке используется запасной вариант —
локальный статический сервер.

### Как понять, что всё сработало

«Рендерится» — ещё не доказательство того, что React общий: remote, который скачал собственный React, тоже отрендерился
бы, но со второй копией на странице. Поэтому тестовая обвязка проверяет сеть:

```ts file=apps/docs-harness/tests/remote.spec.ts at=main lines=25-37

```

До клика с origin руководства ничего не запрашивается. После него первый запрос — манифест с query-параметром против
кэша, затем точка входа с хешем, и ни одного файла с `react` в имени.

### Чего стоит время выполнения

- **Расхождение версий.** Хост собран под контракт 1.0.0; remote, задеплоенный сегодня утром, может реализовывать 1.3.0.
  В пределах одной мажорной версии это нормально, между мажорными версиями — отклоняется. Для этого и существуют пакет
  контракта и его changelog.
- **Новые способы упасть.** Сеть, CORS, кэши и собственные баги remote теперь случаются внутри страницы хоста. У каждого
  есть запасной вариант: таймаут, ссылка на статический сайт, error boundary внутри панели.
- **Стили протекают в обе стороны**, если их специально не изолировать. Remote рендерится в документ хоста, где CSS
  хоста может до него дотянуться, а его CSS — до хоста. Глава «<ChapterLink id="docs-remote" />» решает это с помощью
  shadow root.
- **Нет серверного рендера для remote.** Панель работает только на клиенте, и для справки, которую открывают по клику,
  это приемлемо. Remote, который должен появиться в HTML с серверным рендером, требует федерации и на сервере, а это
  гораздо более крупная настройка.
